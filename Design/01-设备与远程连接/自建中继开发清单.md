# 自建中继开发清单

状态：核心通道已实现，产品化部署与自动路由待实施。依据见同目录 [设备与远程连接设计](设计.md)。下方复合条目仅在完整满足后勾选；核心实现记录见设计文档。

## 目标与首版范围

- 局域网满足客户端安全限制且直连实测可用时优先直连。
- 直连不可用时，通过用户自有服务器转发指定 Link 工作台流量。
- 目标主机主动连出，家庭路由无需开放入站端口。
- 同一设备身份、工作台权限和撤销规则跨直连/中继保持一致。
- 首版支持一个用户自有中继；不包含公共中继池、P2P 打洞、多中继调度、负载均衡或唤醒离线设备。

## 阶段 0：协议与信任边界决策

- [ ] 画清三方链路：客户端、目标主机上的 Link、中继服务器；明确各自的监听方向、连接建立者和数据流向。
- [ ] 评估成熟反向隧道协议/实现，选择具备认证、加密、心跳、自动重连、版本维护和可观测性的方案；禁止为了赶进度实现任意端口代理。
- [ ] 定义中继只转发的工作台路径：HTTP 页面与静态资源、API、Gateway/事件流及确有需要的 WebSocket（含实时语音）。拒绝 owner 管理、SSH、任意路径及非白名单目标。
- [x] 决定首版 TLS 模型：TLS 在用户自有中继终止，浏览器使用公网可信 HTTPS；中继运营者可读取工作台 HTTP 内容及元数据，因此仅面向用户控制的可信服务器，不声称端到端加密。
- [x] 确认 IP 证书路径：Let's Encrypt `shortlived` IP 地址证书有效期 160 小时，必须自动续期；Certbot 5.4+ 支持 IP webroot。HTTP-01 需要 80 端口、TLS-ALPN-01 需要 443 端口，业务仍绑定独立高位端口。已有反代占用标准端口时仅复用其显式 challenge 路由，不接管或静默改写；无可用验证路径则阻止“部署成功”。来源见设计文档。
- [ ] 原生客户端评估证书固定/目标主机身份绑定；不能把 App 的 SPKI 固定能力假定为普通浏览器可用。
- [ ] 定义中继拥塞、数据流量/费用、带宽限制、保留日志策略、升级兼容和最低服务器资源提示。配置与凭据不得进入日志或 URL。
- [ ] 明确浏览器局域网直连能力边界：浏览器不能任意扫描 LAN；HTTPS 到 HTTP 有混合内容限制。只有已经获得可用的 HTTPS/安全上下文入口且实际探测成功，才宣称直连成功；否则回退已配置中继。

## 阶段 1：连接路径模型与状态契约

- [ ] 抽象连接路径：`lan-direct`、`public-direct`、`self-relay`、`unavailable`；可扩展但不预建复杂调度框架。
- [ ] 每个已保存设备保存稳定设备 ID 和授权身份；路径地址/relay ID 属于可更新路由信息，不作为身份本身。
- [ ] 定义状态：已配对、主机在线、路径可达、当前使用路径、中继部署状态，避免将其合并成含义不清的“在线”。
- [ ] 探测使用真实 TLS/身份验证和轻量工作台健康请求；不以同 Wi-Fi、同网段、端口监听或 SSH 命令成功代替端到端探测。
- [ ] 规定连接顺序、超时与重试：快速探测可用直连，失败后切已配置中继；失败分类区分目标离线、DNS/TLS、鉴权、代理未配置、协议升级失败。
- [ ] 切换路径不停止目标主机任务；保留工作台状态、草稿及幂等 request ID，避免重试造成重复操作。
- [ ] 同一路径不得无限重试；退避、取消、网络变化触发重连，并保护长连接/语音流的资源释放。

## 阶段 2：自有中继部署与服务管理

- [ ] 在设备中心加入按需“配置自有中继”，区分“安装开发环境”和“安装连接中继”。
- [ ] 复用现有本机 owner SSH 管理接口、结构化输入和主机指纹核对；密码/私钥按现有策略仅用于操作期，不开放给远程设备或 MCP。
- [ ] 通过 SSH 部署最小中继组件，提供安装、启动、停止、重启、更新、卸载、状态、健康检查及有限日志读取。
- [ ] 检查操作系统、架构、端口占用、systemd 能力、服务器磁盘/内存与出站/入站连通性；逐阶段报告可重试错误。
- [ ] 实现 IP 证书申请/自动续期、现有反向代理 的 HTTP-01 webroot 接入与检查；若标准 challenge 端口被占用且无安全转交方案，明确提示并停止部署。不能把填了服务器 SSH 信息等同于 HTTPS 已就绪。
- [ ] 服务最小权限运行；只绑定必要接口，凭据文件权限受限；默认不开通通用代理/转发功能。
- [ ] 部署后从实际客户端验证证书、配对页、工作台页面/API及需要的 Gateway/WebSocket；全路径通过才标记“可用”。
- [ ] 中继重启后主机可自动认证重连；版本不兼容、证书过期或连接密钥变更应清楚报错，不静默降级。

## 阶段 3：目标主机主动接入与会话转发

- [x] Link 主机作为出站客户端连接自有中继；使用专用中继身份/短期凭据，不复用设备配对 token 或 owner cookie。
- [ ] 建立心跳、在线租约、断线检测、指数退避重连、网络切换恢复和服务关闭清理。
- [x] 中继只允许已登记 Link 主机创建目标通道；拒绝客户端指定任意上游 URL、IP、端口，防 SSRF 和内网横向访问。
- [ ] 将客户端 HTTP、Gateway/事件流与 WebSocket 映射到对应目标主机的 Link 服务；验证 Upgrade、背压、最大帧、超时、并发和断开传播。
- [ ] 不转发或剥离 owner Cookie、Bearer、Forwarded 身份头；重新执行 Host/Origin/路径/方法校验。
- [x] 中继不能自行签发设备授权；设备仍走现有配对申请、主机批准、独立凭据、授权工作台 session 与撤销流程。
- [ ] 中继无法达目标时返回受控错误，不泄露内部地址、栈或秘密。

## 阶段 4：配对、凭据和撤销

- [ ] 配对仍为短时、单次使用；必须由目标主机批准，短码不能脱离已认证路径全球定位设备。
- [ ] 明确中继登记授权与设备工作台授权是两份授权；删除中继不得隐式保留可用接入路径，移除设备也不应误删用户服务器上其他服务。
- [ ] 设备经直连或中继呈现同一设备身份与权限；路径切换不得变成 owner 身份或增加权限。
- [ ] 服务器/域名/证书/中继身份变化时执行重新核验及必要重新配对；防止中继地址被接管后静默导流。
- [ ] 支持撤销某设备、撤销某主机的中继接入、轮换中继凭据及全局关闭中继；撤销立即关闭活动隧道/会话。
- [ ] 凭据只存必要哈希或安全存储，不放 query、日志、前端持久化不安全位置；成功、失败响应不泄露 token 是否存在。
- [ ] 说明中继可见的源/目标标识、连接时间、流量和（若 TLS 终止）内容；提供最少数据保留策略。

## 阶段 5：设备中心与诊断

- [ ] 设备卡片展示目标主机在线、可达状态、当前连接路径和最近错误，不暴露内部 token。
- [ ] 路径状态用清楚文案区分“局域网直连”“公网直连”“经我的中继”“无法连接”。
- [ ] 配置向导显示部署阶段：SSH 信任确认、服务部署、DNS/HTTPS 检查、主机接入、从客户端验证。
- [ ] 自动使用直连优先、中继回退；允许高级用户查看详情与手动重试，但不要求普通用户理解 IP、端口和路由。
- [ ] 无中继且直连失败时明确告诉用户跨网需要可达公网路径或自有中继，并提供配置入口；不能显示假在线。
- [ ] 支持中继在线但目标主机离线、目标在线但浏览器证书错误、HTTP 成功但 Gateway/WS 失败等分层诊断。
- [ ] 保持窄屏、键盘、Android 触控和现有主题一致；设置密钥不回显，危险撤销有明确影响说明。

## 阶段 7：测试与验收

- [ ] 单元测试：路径优先级、探测超时、回退分类、重试退避、凭据过期/轮换、路径切换身份一致。
- [ ] 服务测试：仅白名单路由、SSRF/任意端口拒绝、Host/Origin 校验、owner Cookie 隔离、背压/超限、WS 断开清理。
- [ ] 安全测试：未登记主机不可转发、未批准设备拒绝、token 重放拒绝、设备/主机/中继撤销、证书错配/过期拒绝、错误不泄秘密。
- [ ] 集成测试：LAN 可用时选直连；直连被阻断后选中继；中继断线恢复；目标离线；服务器重启后恢复；仅有中继时完成真实配对和工作台访问。
- [ ] 协议覆盖：HTML/静态资源、主要 API、Gateway 流、权限审批/问题交互、实时语音 WS（若列入首版）；对不支持内容明确提示。
- [ ] 环境覆盖：普通浏览器 HTTPS、Android 原生客户端，至少一种真实家庭 NAT 和手机蜂窝网络。浏览器、App 分别记录 TLS 与证书结果。
- [ ] 记录自动化和真实公网验收边界；测试通过不宣称未实际测试的移动网络或设备能力。
- [ ] 按变更运行 Link/Commander 相关测试、构建、`npm run check` 及 `git diff --check`，不默认跑完整上游套件。

## 建议交付切片

1. **协议验证原型**：单台目标主机主动连单台公网测试服务器；在浏览器与 Android 分别验证安全传输和完整工作台协议，先确定 TLS 模型。
2. **自有中继 MVP**：SSH 部署单中继、主机出站接入、一个客户端经中继连接、设备身份/撤销保持有效；先不做多中继及复杂管理。
3. **路径自动选择**：实测直连优先和失败回退，增加当前路径显示、健康状态与诊断。
4. **产品化部署**：部署/更新/卸载、证书/反代检查、错误恢复、OpenAPI/README、Android/浏览器公网验收。

阶段 1 之前应先完成阶段 0 的 TLS 与信任边界决策；如果浏览器所需 HTTPS、主机身份校验或数据可见性没有可靠方案，不应直接进入面向用户的“随处连接”承诺。
