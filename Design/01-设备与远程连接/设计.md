# 我的设备：统一连接设计

状态：现有直连及自建中继核心通道已实现；一键部署与路径自动选择待实施。本文区分已实现能力、后续目标与验收结果。

## 定位与边界

面向一个人拥有多台电脑、手机和自有服务器。统一入口「设备」，统一设备列表、配对、进入工作台、重命名和撤销。任务始终在目标主机运行，切换设备不迁移或停止任务。

连接目标：满足浏览器和网络安全条件时，局域网优先设备直连，以获得低延迟；异地且直连不可达时，可经用户自行部署和管理的中继连接。产品不提供公共中继池，不要求用户购买专用服务器，已有服务器可复用。中继只转发指定 Link 工作台流量，不开放 owner 管理接口或任意内网端口。自动路径选择尚未实现；未配置自有中继且无现成公网路径时，跨网连接不可用。

「随处连接」要求目标主机开机、联网、Link 运行且中继可达，不承诺唤醒离线主机或在任意网络下永远可用。用户自有服务器承担中继入口及转发流量的资源成本。

## 用户路径

1. 局域网已有小角：设备 → 添加设备 → 连接已有设备；主机「允许其他设备连接」，展示二维码、一次性配对信息和请求。手机扫码、电脑粘贴；短码必须结合已知主机地址使用，不宣称可仅凭短码全球定位。支持自动发现时才展示附近设备，不伪造发现结果。
2. 云端已有小角或目标已有可达公网 HTTPS：同一添加入口，扫描或粘贴 HTTPS 配对信息，目标主机批准后保存设备身份。之后从列表直接进入。HTTPS/DNS/反代可达性仍是实际部署条件。该路径连接的是本身可达的目标，不等于中继任意内网设备。
3. 空白服务器：设备 → 添加设备 → 安装到服务器；填写 SSH 地址、端口、用户和认证信息，核对主机指纹；复用现有安装服务部署官方引擎与自有插件、启动并检查连接、完成授权和设备注册。安装失败显示所在阶段、可重试，不把「命令执行成功」当作「连接成功」。无公网 HTTPS 时明确区分仅本机 SSH 隧道可用与手机可直接连接，不承诺自动拥有域名证书。
4. 已保存设备：点击进入；目标连接策略（自动选择待实施）先尝试当前网络下可用的直连路径，直连不可用时使用已配置的用户自有中继；两种路径均不可用则说明状态与恢复操作。离线可重试、重命名或移除；主机可撤销授权。保留当前工作台与草稿。
5. 启用随处连接（待开发）：在设备中心添加/选择自有服务器，确认 SSH 主机指纹后部署或登记中继服务；目标主机主动建立出站认证连接；手机及其他设备经此服务器访问目标工作台。部署成功必须验证客户端经中继完成真实工作台访问，单纯 SSH 命令成功不算可用。已有公网路径或 VPN 可继续复用，不强制走中继。

## 信息架构与交互

设备中心集中呈现「我的设备」「添加设备」「允许其他设备连接」。添加设备保留「连接已有设备」「安装到服务器」；「配置自有中继」作为按需连接能力，不与运行开发环境的目标设备安装混淆。手机与电脑使用同一语义，不再使用「连接手机」「添加电脑」「App 地址」作为主流程。扫码、复制连接信息、输入配对信息提供等价入口。

监听地址、端口、网络模式、公网 URL 与旧访问密钥收于高级设置；正常路径只呈现必要操作。使用既有组件、图标与主题，不引入新设计系统。支持窄屏、键盘、加载、等待批准、拒绝、过期、离线、失败及重试。

## 配对与认证

复用 Link 的 TLS、一次性五分钟配对令牌、主机批准、独立设备凭据、HttpOnly 工作台会话与撤销机制。短码必须限流、过期、单次使用，不将永久凭据放进 URL 查询或日志。

目标：正常设备连接只需一次配对，不额外要求重复输入云端访问密钥。现有云端访问密钥保护的是全站，不能直接关闭、放行 owner 管理接口，或让 Link token 获得 owner 身份。整改应只将经过认证的 Link 配对工作台交给设备授权保护；管理入口继续保留独立保护。若现有反代不能安全兼容，保留旧防护并明确兼容提示，不静默降低权限。

SSH 仅允许本机 owner 管理接口调用，不开放给远程设备/MCP 任意执行命令。凭据不写日志、默认不持久化。核对 SSH 主机指纹，避免不校验 host key 的自动安装。安装和配对使用明确的结构化接口，校验输入，避免 shell 注入。

首个可运行切片采用 TLS 在用户自有中继终止：浏览器访问用户配置的公网 HTTPS 源，中继认证已登记主机并转发受限的 Link 工作台路由；目标主机主动使用 TLS 连接中继。该模式兼容普通浏览器与现有工作台 Cookie/Origin，但中继运营者能够读取转发中的工作台 HTTP 内容和元数据，因此只面向用户控制的可信服务器，不宣称端到端加密。IP 地址证书采用 Let's Encrypt ACME `shortlived` profile（160 小时有效），必须自动续期。ACME 地址验证需公网 HTTP-01 的 80 端口或 TLS-ALPN-01 的 443 端口；业务服务仍使用独立高位端口。若 80/443 已被现有反代占用，应通过其已有配置转交 HTTP-01 challenge，不接管端口、不自动改写现有服务；否则需明确提示此约束，不能宣称一键部署成功。Certbot 5.4+ 支持 IP 地址 webroot 流程。来源：Let's Encrypt [IP 地址证书 GA 公告](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability.html)、[Certbot 支持说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot.html)、[挑战类型与端口要求](https://letsencrypt.org/docs/challenge-types/)。原生 App 的主机身份绑定不替代浏览器 TLS 信任。

首阶段聚焦单个用户自有服务器、显式部署/更新/健康检查/卸载及稳定的反向隧道；不实现公共中继池、自动计费、P2P/NAT 打洞或多中继调度。采用专用、受认证的 Link 工作台反向通道，不允许客户端指定上游地址/端口。部署前检查自选高位端口占用并展示所需防火墙规则；不得接管已有 SSH/HTTP/HTTPS 端口，且不能仅凭 SSH 可达就声称公网服务可达。自动发现如无可靠已有实现，不作为已完成功能宣传。

## 统一设备视图修订（已实现）

### SSH 中继向导与连接选择（本轮实施约定）

设备中心单独提供“部署自有中继”，不改变原 SSH 安装云端工作台。先核对 SSH 指纹，再提供凭据；部署作业完成公网证书验证后，将主机连接密钥通过本机 owner 回调写入 0600 配置，网页状态不返回密钥。支持状态、日志、启停、重启及显式卸载；不抢占已有端口，不自动修改防火墙。HTTP-01 必须公网 80，已占用时需要用户明确提供现有站点 webroot；业务使用空闲高位端口。续期失败保留旧证书，不能承诺 100% 可用。

中继配置与 Link 监听配置独立保存，禁用中继不关闭局域网服务。现有环境变量保留为启动配置；owner 显式保存优先。桌面负责一键部署，Android 能连接中继地址；没有部署桥能力时不展示可点击部署入口。

自动选路仅接受配对主机通过已认证 TLS 通道提供的候选地址；直连使用固定 SPKI，中继使用系统 CA。仅建连前网络不可达可回退，授权拒绝或证书异常不得降级，不重放写请求、不迁移活动流。未完成原生或浏览器路径不得标为已实现。
