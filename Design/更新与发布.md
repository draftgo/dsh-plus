## 已实现

- 侧栏底部「更新」图标位于用量日志左侧，有新版本时显示红点；设置使用图标按钮。以 DSH-Plus 插件为主要更新项，界面、工具集成、Voice 与 Link 的主机端随插件一起升级。
- 会话仅在已完成且未读时显示绿色；读取后恢复 DeepSeek、Codex 等工具图标。直接复用官方 `completionUnread`，不将历史停止会话一律当成未读；运行中蓝色、等待交互黄色，工作区仅显示当前运行或等待状态。
- 供应商模型 ID 在选择、保存、重载和请求时保持原值，不将 ASR/TTS 的网关别名替换为厂商模型名。重复选择当前语音供应商不清空设置，修改实时地址保留路由参数；已有配置被旧版改写时需重新选择模型，不能猜测恢复。编码工具显式模型优先于默认方案，切换模型保留完整会话绑定及快捷配置。
- 源码服务器部署显示「此主机由服务器部署管理」，不提示安装新版 Windows 应用。清单尚未发布的 HTTP 404 显示「更新通道尚未就绪」；签名、权限或安装包请求失败仍作为错误处理。
- 默认国内加速 `https://ghfast.top/`，可切换 GitHub 直连或自定义 HTTPS 镜像。失败保留当前选择，不静默切源。
- 桌面面板提供「检查应用更新」，调用官方 Desktop bridge；Windows 原生「应用 → 检查更新」检查整包应用（Electron、Harness 及离线插件种子）。原生自动更新固定走内置国内源；面板中签名清单提供的应用安装包链接跟随所选来源。
- 手机操作的是当前连接主机。插件安装、检查与回退都发生在 Windows；主机重启后手机重连/刷新工作台即可，无需重装 APK。Android 原生能力变化仍需更新 APK。
- 插件完整包包含生产依赖和已构建客户端，通过 Ed25519 签名清单、SHA256、尺寸、引擎范围、平台及架构校验。解包拒绝路径穿越、链接、重复路径及超额内容。
- 插件版本存于用户 profile 的 `.dsh-plus/releases/`，不可变版本目录准备完成后，在官方 profile 写锁内原子切换 manifest；保留上一版用于回退。正在运行的代码不被覆盖，升级与回退均需重启主机应用后生效。
- 有正在运行或等待交互的任务时禁止安装/回退，下载结束再次检查。下载、检查、配置和激活互斥；失败保留可运行版本。
- 官方 runtime 不携带 Plus 包；离线种子在 `resources/dsh-plus/seed`。安装器使用随应用提供的 Node 完成首次 profile 登记，用户无需另装 Node 或包管理器。profile 通过 `link:` 直依赖完整组合包，使插件列表可见，并避免官方包管理器重复安装私有依赖，名称显示 DSH-Plus。

## 首次迁移

已发布的旧版将 Plus 放在内置 runtime，且没有 Plus 的应用更新源。需要手动安装一次新版 Windows 安装包，迁移为外置插件；之后日常更新通过侧栏完成。不能用 profile 中的同名包覆盖旧内置包，因为官方解析优先选择安装目录。

迁移保留用户工作区、会话与配置；曾主动关闭插件的状态保留。内部 `commander` API、数据目录和兼容标识继续保留，用户界面及提示统一为 DSH-Plus，插件包名为 `dsh-plus`。

## 发布

1. 首次配置：客户端信任公钥为 `plugins/commander/shared/update-public-key.pem`。对应私钥保存在被 Git 忽略的 `.local/release-keys/dsh-plus-update-private.pem`，已配置 GitHub Actions Secret `DSH_PLUS_UPDATE_PRIVATE_KEY`；维护者需另行安全备份。不要提交私钥。`create-update-key.mjs` 拒绝覆盖已有密钥。
2. 日常更新：递增 `plugins/commander/package.json` 及 lock 根包版本，运行 `DSH-Plus plugin update` 工作流。Windows 构建完整依赖包，签名清单；默认只生成 Actions artifact，显式启用 publish 才发布。
   应用版本由根 `package.json` 管理，与插件版本独立；Android `versionName` 对齐应用版本。只更新插件时无需递增应用版本或重建安装包。
3. 插件版本发布为不可变 `plugin-v<version>`，签名元数据更新到独立 `plugin-updates` Release。两者分离，避免桌面应用发布改变 GitHub latest 后干扰插件检查。
4. 应用更新：运行 `DSH-Plus Windows installer`，通过打包后运行与静默安装检查，再运行 `Publish verified Windows installer`。发布安装包、SHA512 `latest.yml` 及 blockmap 到独立 `app-updates` 渠道。不会使用官方 DeepSeek 应用更新源。
5. 插件清单默认精确锁定已验证 Harness 版本。升级引擎须遵循 upstream.json / 子模块 pin 约定，完成兼容验证后发布新的插件和应用。
6. Android：递增 `plugins/link/mobile/android/app/build.gradle` 的 `versionCode` / `versionName`，运行 `DSH-Plus Android package` 并开启 publish，校验持久发行签名、版本与内嵌资源后上传正式 APK 到对应应用版本 Release；debug 仅供本地开发，不进入正式发布。

原生应用更新仍使用官方 electron-updater 的下载、校验和安装流程；插件更新使用独立签名信任链。两个发布渠道均指向 `draftgo/dsh-plus`。

发行仓库必须允许匿名下载，国内镜像同样无法读取私有 Release。经用户授权，`draftgo/dsh-plus` 已于 2026-10-18 改为公开仓库；客户端不携带 GitHub 凭据。

## 验证边界

本地可验证插件打包、签名清单、更新 API、React 交互、官方 profile 解析、版本切换与回退。Windows 安装器构建、NSIS 升级、原生自动更新和手机真机重连由 Windows 工作流及设备验收；Linux 工作区不能替代这些验证。

只有签名清单及其引用的完整版本包均发布成功，已有客户端才有可下载的新版本；发布后验证 GitHub 与默认国内镜像的清单、签名和包地址，不将界面「已接入」等同于「已经分发」。
