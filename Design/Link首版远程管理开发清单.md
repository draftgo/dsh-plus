# Link 首版远程管理开发清单

日期：2026-10-16。状态：**首版源码已实现；构建与验收结果以[实现记录](Link入口与移动端实现记录.md)为准**。本文保留需求、取舍和验收清单，未勾选项不代表已完成。

## 首版决定

在 DSH-Plus 内提供「远程连接」入口，由 Link 提供网络、配对与设备管理。用户只需安装/升级一次 DSH-Plus，不要求再手动装一个服务、注册云账号或配置公共中继。

采用两种连接模式、同一套会话能力：

| 模式 | 使用方式 | 必要条件 |
| --- | --- | --- |
| 局域网 | 主机点启用 → Android App 扫码 → 主机确认 → 操作会话 | 主机运行、同网且互通、允许应用入站；无需域名和云服务器 |
| 公网 | 用户配置自己的 HTTPS 地址 → 手机网页或 App 配对 | 实际运行 Harness 的主机可从该地址访问、可信证书、正确配置的反向代理 |

同一 Wi-Fi 下直接通信，无需「局域网中继」。公网模式也不依赖 `dsh.r2049.cn`。家里电脑没有公网入站路径时，仅有一个域名或一台无连接隧道的云服务器不能让手机流量访问它；这属于后续 VPN/自建中继扩展，不混入今晚首版。

执行主机既可以是家里的桌面电脑，也可以是云服务器。连到云服务器只操作该服务器上的项目和会话，不会自动连回家里的电脑。

## 手机与电脑的范围

- **Android App 纳入首版目标**：为免域名的局域网连接提供原生扫码、主机信任校验和安全凭据存储。采用 Kotlin 原生传输、扫码与安全存储，复用 React 移动界面；参考 Remote 的职责分层，不整体搬运其账号和中继系统。
- **iPhone 首版支持公网 HTTPS 网页**：跨平台 App 保留 iOS 边界，但 iOS 安装包、签名、分发和实机局域网验证单列；不能把 Android APK 当作 iPhone 交付。
- Windows/macOS 的浏览器可使用公网 HTTPS 入口；桌面 Host 的实际支持以官方 Harness 和现有 DSH-Plus 兼容性为准，需分别验证。
- 普通手机浏览器访问局域网 IP 的 HTTP 页面，不作为正式加密连接方案；自签名 HTTPS 的浏览器警告也不作为正式引导。首版不承诺 iPhone 免域名局域网接入。
- 远程管理范围是项目与 Agent 会话，不包含操作系统桌面投屏、键鼠控制。

App 的价值在于原生连接与设备信任，不能只把一个网页套进 WebView。后台恢复以主机状态为准，不承诺 Android/iOS 永久在线。

## 复用原则和边界

1. **一个执行主机、一个权威状态**。手机操作原会话，不另起一份 DSH-Plus/Harness，也不通过同步数据库伪造同一会话。
2. **官方会话走官方连接契约**。复用官方 Connection/Host/Client 能力与 DSH-Plus 适配器；`plugins/commander/src/web.mjs` 的直接会话写操作有 `commander-web:` 所有权限制，不能移除这个限制来支持手机。
3. **Link 只负责连接**。管理入口放在 DSH-Plus，服务实现放 `plugins/link/`，移动端放 `plugins/link/mobile/`。现已随 DSH-Plus 构建并打入插件，不要求单独安装 Link。
4. **原生端复用业务契约**。通过适配层调用官方会话操作与事件，不复制 Agent 执行引擎。自有 DSH-Plus 能力仍走已有权限和归属规则。
5. **设备授权说清楚**。首版优先做可信个人设备授权；若官方接口只支持当前用户权限，界面明确说明等同主机用户访问，不伪称已经支持按项目细分授权。不增加万能 shell 接口。

官方 Desktop 已有共享 Web Host，但网络暴露、浏览器身份与原生端 peer 不能直接视为已兼容。首个开发步骤必须验证能否仅通过自有插件/配置复用同一个运行时，禁止修改官方子模块源码或启动另一份 Harness 规避问题。

## 连接与配对设计

### 局域网：原生客户端 + 主机证书绑定

首选方案是 Link 提供局域网 TLS 入口，主机本地生成并持久化证书/身份，二维码携带地址、主机证书公钥指纹和短时一次性配对凭据。App 用原生网络适配层校验证书绑定；不以关闭证书校验实现连接，也不要求用户安装系统 CA。

原生 HTTP 请求和实时事件连接都必须使用相同主机绑定。证书绑定不自动适用于 WebView、JS fetch 或某个 WebSocket 库：必须先做 Android 原生传输验证，确认所选成熟组件能覆盖请求及事件流。二维码不携带长期授权，配对信息不写访问日志；手工录入提供与扫码等价的短期配对流程及主机身份核对。

主机确认设备后签发可撤销授权，App 存入平台安全存储。换证书/主机身份后重新确认；首版地址变化需要清除本机身份并重新扫码确认；自动迁移连接地址留待后续。只在用户启用时监听明确的网络接口，支持多网卡选择与端口冲突提示，停用后释放监听。

若证书绑定或官方认证衔接的技术验证未通过，不降级到明文或无校验连接，也不把局域网能力标记完成；立即汇报具体阻碍与剩余工作。

### 公网：用户自有 HTTPS 地址

主机配置对外地址，提供反向代理示例与复制入口；首版没有外网可达性自动探测，保存成功仅表示配置有效。手机打开网页或在 App 输入/扫码同一地址。公网网页与静态资源、API、实时流优先保持同源，不要求用户再管理多个域名。

验证证书、外部 Host/Origin、浏览器 Cookie、会话事件流及代理超时。官方 Cookie 策略与实际载体协议有关，不能只填写 `publicUrl` 就宣称反向代理 TLS 已工作；需验证所选受支持配置的端到端登录流程。首版先支持独立域名根路径，子路径部署后续扩展。

公网网页也须有配对确认与撤销机制，不把官方进程级登录令牌当成永久二维码，更不把已配对设备变成不可区分的同一个共享密码。

### 共用行为

- 配对有效期、单次使用、主机确认、失败限流；未配对设备不能浏览项目/会话。
- 设备列表、连接状态、上次活动和撤销；撤销后阻止新请求并断开已有流。
- 任务留在主机运行；手机断网、切后台、重开 App 后重新拉取权威状态与缺失事件。
- 写请求带唯一请求 ID；不确定是否成功时先查回执，不自动重复执行。审批重试不能重复应用。
- 优先复用官方事件/恢复机制，界面按短间隔合并渲染；不要另造并行事件日志或为每个 token 单独持久化。

## 今晚开发顺序与清单

以下是执行顺序，不是对未经验证工作量的保证。**局域网与公网都属于 P0**；不能只完成一个然后把另一个写成可选。App 安装包是局域网验收的依赖。

| 顺序 | 开发事项 | 完成标准 |
| --- | --- | --- |
| 0 / P0 | 官方 Host 与原生 TLS 技术验证 | 同一运行时能提供静态页面/会话能力；Android 请求与事件流校验绑定；不绕过会话归属和审批 |
| 0 / P0 | Android 构建准备，与 Host 验证并行 | 明确 JDK/SDK、构建命令和依赖；最小原生 App 能构建安装。不能用 JS 导出冒充 APK |
| 1 / P0 | Link 生命周期与打包 | 随 DSH-Plus 安装；启停、监听地址、端口占用、配置保存有效；不改上游源码 |
| 2 / P0 | 两种模式与设备配对 | LAN 二维码；公网地址检查与配对；主机确认、过期重放拒绝、设备撤销有效 |
| 3 / P0 | 共用会话适配层 | 项目列表、已有/新建会话、模型选择、历史、实时输出、发送、取消、审批和追问形成闭环；只展示后端支持的操作 |
| 4 / P0 | DSH-Plus 完整入口 | 设置内「远程连接」：模式、启停、地址/二维码、待确认设备、已授权设备、撤销及故障提示 |
| 4 / P0 | Android 完整入口 | 扫码/手动添加、单主机安全记忆、清除重配、会话操作、连接状态、断线恢复、删除设备授权；大输入框与软键盘交互可用 |
| 4 / P0 | 公网手机网页 | 使用同一授权与会话语义；优先复用官方 Web UI，再补必要的移动适配，不另写完整聊天引擎 |
| 5 / P0 | 重连与幂等 | 流中断后补齐历史；恢复时无重复发送、重复任务、重复审批；连接失败有明确重试入口 |
| 6 / P0 | 集成验收与打包 | 两条网络路径分别有端到端记录；Android 有可安装构建产物才算 App 交付；未实测端明确列出 |
| P1 | 使用体验优化 | 记住主机、快速切换、局域网地址变更辅助；mDNS 自动发现按工期追加 |

并行边界：Host/配对、移动端、Web/桌面入口可在步骤 0 通过且接口契约确定后分开开发；会话归属、授权、恢复由集成负责人统一核对。

本轮在忽略提交的 `.local/link-toolchain/` 安装隔离 JDK 17、SDK 35 和 Gradle 工具链，不修改系统 Java 配置。实际 APK 构建结果及未测端见实现记录；不依赖外部收费构建服务。

## 首版验收

- [ ] 新用户升级 DSH-Plus 后能找到入口，无需手动部署另一套服务。
- [ ] Android 与主机在可互访局域网：无域名、无公共中继，安装 App 后扫码、确认并操作同一会话。
- [ ] 手机切到蜂窝网络：经用户自己的 HTTPS 地址配对、读取输出、发送消息、取消任务并处理审批；iPhone Safari 也走通公网路径。
- [x] 独立真实 Harness 联调：远端 API 操作同一个官方会话，项目、模型、历史与流式输出一致；手机 UI 实机仍待验收。
- [ ] 未配对、过期凭据、配对重放和已撤销设备无法继续访问；原生端拒绝错误证书身份。
- [ ] 断网、切后台、重开 App、重复点击发送与审批：任务继续，恢复后不重复执行，界面明确显示状态。
- [ ] 能识别端口占用、防火墙/网络隔离、主机离线、证书不可信、域名不可达；不把所有失败显示成一个「连接失败」。
- [x] 实现记录分别列 Windows/macOS、Android、iPhone 的构建与测试边界；无设备时明确标注。
- [ ] 完成契约测试、插件打包、Android 构建与两条真实网络路径验收（服务联调及插件构建已通过，设备与外部网络验收仍待完成）；根 `npm run check` 仅作仓库一致性检查。
